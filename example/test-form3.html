pdftoformext — manual test form 3

The fixture for this page is example/test-form3.pdf: a two-page, text-only SAP proposta comercial (sales quotation) from a fictional supplier, Ferrax, to a fictional customer, Mineradora Pedra Grande. It has no AcroForm at all, so all 296 of its keys come out of the geometric pass under table.* — 15 blocks, of which only tables 2, 4 and 5 have a header row (≥3 columns); everything else is a two-column label/value block or a run of prose.

This page is the other side of that document: the buyer's supply portal, where a quotation that arrived as a PDF gets keyed in by hand. That is the workflow the extension exists to remove, so map a section, hit Fill page, and check it against the PDF.

Expected keys are in HTML comments beside each field so a run can be checked; the extension never reads them. Fields marked ⚠ are the interesting ones — a coercion that has to do real work, or one that is supposed to fail.

Documento do fornecedor

Table 1 is the title block; its cells scatter across four columns because the title, the document number and the date line are centred at different widths, so every key here is positional.

Organizational block — table 2 is one of the three with a real header row, so the picker's column strip reads ORG. VENDAS … MOEDA rather than C0/C1. Row 0 is the header row and shows up as an ordinary body row; the values are all in row 1.

Partes envolvidas

Table 3 is a two-column block: the ordering party (AG) on the left, the goods recipient (WE) on the right, seven rows each. Two columns means no header row is inferred, so each cell's label comes from the cell to its left — which is why the right-hand column's entries read sensibly in the picker and the left-hand ones don't.

Referências e condições da consulta

Table 4, the second headered block. All six values are in row 1.

Itens da proposta

Eight items, positions 10–80. Each item's description spills onto one or two continuation rows in the PDF (r4, r5, r7, …), which the extraction keeps as their own cells in column 2 — so the second description field of each row exists to catch them. Quantities and prices go into number inputs, where toNumber has to read Brazilian 18.470,00 as 18470.

Totais

Table 6 interleaves two things that are side by side on the page: the fiscal note runs down column 0 while the totals sit in columns 1 and 2, so the rows alternate between them and the totals land on rows 1, 3, 5, 7 and 8. The grand total is its own block, table 7.

Texto e anexos

Long prose is one cell per printed line, not one cell per paragraph — the geometric pass has no way to know a wrapped line continues the one above it. So each textarea below takes one line, and reassembling a paragraph means mapping several fields or copying by hand. Worth seeing before promising anyone that a quotation "imports itself".

Parecer de suprimentos

Nothing in this block comes from the PDF — it is the buyer's own decision, filled in by a person. It is here because the first three inputs have no id and no name, so mapping one forces the :nth-of-type path, the last candidate selectorsFor() has (the radios below do have a name, and get the usual [name="decisao"][value="…"]). Map the Justificativa field to any key and confirm the structural selector resolves.

Não tocar — controle do invariante

Pre-filled with sentinels whose labels and names are deliberately close to fields that are mapped above. Never map these. After Fill page, all four must still read exactly as below — that, and not the count in the status line, is the test.
